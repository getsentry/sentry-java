# Nav2 and Nav3 Samples

## Nav Sample Transaction Tips

When inspecting route-level transactions from `Nav2Activity` or `Nav3Activity`, note that the sample app also enables automatic Activity
tracing by default. That can produce overlapping `ui.load` transactions for the Activity itself, which may make it harder to isolate the
navigation transactions generated by the Nav2 or Nav3 integrations.

If you want the route transactions to be the primary trace surface while testing those sample screens, temporarily disable automatic
Activity tracing in `src/main/AndroidManifest.xml`:

```xml
<meta-data
  android:name="io.sentry.traces.activity.enable"
  android:value="false" />
```

This is mainly useful for debugging and comparison in the sample app. It is not a general recommendation for production apps.

## Navigation Performance Scenarios

Both navigation samples include an interactive performance scenario for exercising stack mutations and route rendering.

### Nav2

Open Nav2 from the integrations screen, select the `Performance` tab, and use the controls to build a stack or replace the top destination.
The sample also supports automatic recompositions and navigation for sustained stress testing.

### Nav3

Open Nav3 from the integrations screen, select the `Performance` tab, and use the presets or performance controls to run a scenario with the
desired stack depth, workload, integration mode, and argument shape.
